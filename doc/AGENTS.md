## 文档即源码

- `README.md` 是文档地图；project/decisions/diff/env 四篇为规划稿，随实现持续更新
- `doc/` 只收与项目架构、实现相关的文档；提交规范、工作流等约束/约定不入 doc/（提交格式放 `.agents/rules/`）；归属拿不准时先确认再放
- 引用一律 markdown 链接（跨文件 `[x](file.md#锚点)` / 站内 `[x](#锚点)`），不用裸编号
- `decisions.md` 的 ADR 编号 `D-xx` 连续递增，标题不含 `、（）+` 等标点
- 改完 doc 必须跑锚点一致性检查，退出码非 0 = 有不匹配：
  `uv run --directory script check-links.py`

## 方案状态标记（doc/ 写作约定）

doc/ 中出现「当前方案 vs 预留备选 vs 被替换」多候选时，用统一标签标记，分**行内简记**与**块记**两种格式，标签文字两种格式下必须一字不差：

- **`【当前】`**：当前选择并生效
- **`【备选】`**：预留方案，仅当触发条件成立才实现/替换
- **`【已否决】`**：经论证被否定的替代方案（未实现）
- **`【已替换】`**：曾实现/曾为主案，后被某原因替换

**行内简记 = 链接**：用于表格单元 / 一句话提及。标签 + 方案标题作为链接文本，指向对应块记的小标题锚点：

```markdown
[【当前】 v1 行为：更新追最新，path 策略](#v1-行为更新追最新path-策略)
```

**块记 = 独立小标题 + admonition callout**：用于需要多行展开的方案详情。每个块配一个独立小标题作锚点（标题只写方案名、不含标记，保锚点干净），紧接 callout：

```markdown
#### v1 行为：更新追最新（path 策略）
> [!IMPORTANT] 【当前】 v1 行为：更新追最新，path 策略
> 
> v1 不开放版本历史 UI。更新后阅读位置按章节路径映射到新版本……

#### 方案 D：版本快照绑定
> [!NOTE] 【备选】 方案 D：版本快照绑定
> 触发：M5 版本功能开放
> 
> 阅读位置与具体 commit 强绑定……
```

- callout 类型 ↔ 标签映射：`【当前】`→`[!IMPORTANT]`、`【备选】`→`[!NOTE]`、`【已否决】`→`[!CAUTION]`、`【已替换】`→`[!WARNING]`
- callout 标题行 = 类型 + 标签 + 方案标题；`【备选】`/`【已否决】`/`【已替换】` 的块内第一内容行紧跟 `触发：…` / `原因：…`，随后一行 `> `（仅 `>` 加一个空格）空行，再写方案内容详情；`【当前】` 无触发/原因行，直接 `> ` 空行后接内容
- 块记可被行内简记跨文件链接（`[【当前】 …](decisions.md#小标题锚点)`）
- 方案状态变化时同步更新标记与触发/原因，避免误导后续会话

## 文档存档（结构调整/精简前）

- 对 doc/ 做结构重组、精简、整篇重写前，先整体快照：新建 `archive_doc_v{num}/`，`num` = 现有存档最大编号 + 1（当前 `archive_doc_v2` → 下个 `v3`）
- 快照 = 复制本目录顶层全部文件（README、AGENTS.md、四篇文档、mdor.c4），**不含任何 `archive_doc_v*` 存档目录**，复制完再在顶层调整
- 旧存档永不删除；`archive_doc_v1/` 为历史归档，勿改

## L2 单详述源

- 同一主题只在 `project.md` 一处详述，不分散到其他文档
- `diff.md` 只写平台差异增量、`decisions.md` 只写论证
- 其余内容一律以链接回指、不复述
- **引用方向**：事实的源放「该事实所属层」（版本→`env.md` §1、规范决策→`project.md`、ADR→`decisions.md`、平台差异→`diff.md`）；其他层一律链接回指、不复制正文；**新增引用方向时同步补充反向链接**（源侧被引用后，在被引用层维护「规范位置 / 依据」反链，如 decisions 各 D-xx 的规范位置列回指 project/diff）
- **互引不算环**：允许跨层上下互指（反向链接是既定设计），判定标准是「同一份事实是否存在第二个源」
- **确定信息同样单源**：对抽象层级低、易被反复修改的确定信息（如依赖的确定版本、当前决策执行的方案），同一原则适用——只一处落值（依赖版本 → `env.md` §1，见「版本号事实落点约定」；当前方案 → 方案状态标记的块记），其余出现处一律链接引用、不复制具体值/正文，防止改一处漏一处。文档层级关系见 [README 文档间引用关系](README.md#文档间引用关系)

## 版本号事实落点约定

- 版本号（rust / MSVC / NDK / JDK / dioxus-cli 等）的事实源 = [env.md §1 版本矩阵](env.md#1-环境总览与版本矩阵)（承接 [project.md §12.3](project.md#123-ci-与发布github-actions) 已定的「版本单一事实源 = env.md §1」）
- 安装/构建命令里内联的具体版本号（如 `cargo install dioxus-cli --locked --version 0.7.10`、MSVC 组件 ID `VC.14.50.18.0.x86.x64`）是**命令参数**，与 §1 矩阵是同一事实、不构成第二个事实源；命令必须内联具体号以保证可复制粘贴复现
- 升级时同步改两处：§1 矩阵 + 引用该版本的命令（对齐 [env.md §4 依赖升级](env.md#4-依赖升级)）
- 判定标准不变：同一份事实只存在一个源（§1 矩阵），命令参数不算第二源
