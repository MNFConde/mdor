## 方案状态标记（doc/ 写作约定）

doc/ 中出现「当前方案 vs 预留备选 vs 被替换」多候选时，用统一标签标记，分**行内简记**与**块记**两种格式，标签文字两种格式下必须一字不差：

- **`【当前】`**：当前选择并生效
- **`【备选】`**：预留方案，仅当触发条件成立才实现/替换
- **`【已否决】`**：经论证被否定的替代方案（未实现）
- **`【已替换】`**：曾实现/曾为主案，后被某原因替换

**行内简记 = 链接**：用于表格单元 / 一句话提及。标签 + 方案标题作为链接文本，指向对应块记的小标题锚点：

```markdown
[【当前】 v1 行为：更新追最新，path 策略](#v1-行为更新追最新path-策略)
```

**块记 = 独立小标题 + admonition callout**：用于需要多行展开的方案详情。每个块配一个独立小标题作锚点（标题只写方案名、不含标记，保锚点干净），紧接 callout：

```markdown
#### v1 行为：更新追最新（path 策略）
> [!IMPORTANT] 【当前】 v1 行为：更新追最新，path 策略
> 
> v1 不开放版本历史 UI。更新后阅读位置按章节路径映射到新版本……

#### 方案 D：版本快照绑定
> [!NOTE] 【备选】 方案 D：版本快照绑定
> 触发：M5 版本功能开放
> 
> 阅读位置与具体 commit 强绑定……
```

- callout 类型 ↔ 标签映射：`【当前】`→`[!IMPORTANT]`、`【备选】`→`[!NOTE]`、`【已否决】`→`[!CAUTION]`、`【已替换】`→`[!WARNING]`
- callout 标题行 = 类型 + 标签 + 方案标题；`【备选】`/`【已否决】`/`【已替换】` 的块内第一内容行紧跟 `触发：…` / `原因：…`，随后一行 `> `（仅 `>` 加一个空格）空行，再写方案内容详情；`【当前】` 无触发/原因行，直接 `> ` 空行后接内容
- 块记可被行内简记跨文件链接（`[【当前】 …](decisions.md#小标题锚点)`）
- 方案状态变化时同步更新标记与触发/原因，避免误导后续会话

- 对 doc/ 做结构重组、精简、整篇重写前，先整体快照：新建 `archive_doc_v{num}/`，`num` = 现有存档最大编号 + 1（当前 `archive_doc_v2` → 下个 `v3`）
- 快照 = 复制本目录顶层全部文件（README、AGENTS.md、四篇文档、mdor.c4），**不含任何 `archive_doc_v*` 存档目录**，复制完再在顶层调整
- 旧存档永不删除；`archive_doc_v1/` 为历史归档，勿改
